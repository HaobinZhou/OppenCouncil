# Council 使用与部署

Council 是 [OppenCouncil](../README.md) 的网页工作台。它将一个或多个项目中的方案、讨论、候选口径与正式版本集中呈现，供人在浏览器中审阅。首次安装和 skill 软链接设置见 [快速开始](../README.md#快速开始)。

**本页命令均从 OppenCouncil 仓库根目录运行。**

## 打开项目

先让 AI 使用 Stepwise R Project 或 Oppen Project Steward 准备项目和本轮问题，然后运行：

```sh
uv run --project council oppencouncil open /absolute/path/to/project --port 5322
```

`open` 登记该项目并启动或复用工作台，返回首页及项目访问链接。默认监听 `127.0.0.1:5322`；首次打开网页时设置站点密码，以后输入密码登录，无需用户名。项目目录只列出已登记且启用的项目，网页不能浏览或登记任意本机文件夹。

支持原生 Stepwise R 和 Steward v3/v4 项目。普通文件夹需要先由相应 skill 初始化或接入；已有项目沿用原来的治理方式。双重治理标记和以符号链接作为项目根目录的登记会被拒绝。这里的限制针对项目根目录，不影响全局 skill 采用软链接安装。

```sh
# 查询服务地址
uv run --project council oppencouncil status

# 查询某个项目的访问链接
uv run --project council oppencouncil status /absolute/path/to/project

# 暂时从站点移除项目，保留其文件和口径记录
uv run --project council oppencouncil disable /absolute/path/to/project

# 停止整个站点
uv run --project council oppencouncil stop
```

服务在启动它的终端或 AI 会话结束后继续运行；关闭浏览器不会停止服务。电脑关闭或休眠后，远程页面会断开。再次 `open` 可以重新启用项目并启动服务。

## 审阅与继续讨论

- **找到问题**：按标题、编号、状态或领域筛选。相互关联的问题放在同一个主题内，成员可以展开查看；题目与主题各有可返回的 URL。
- **比较方案**：同时显示最多两个完整方案，更多方案可切换。方案正文、影响和代价支持 Markdown，长文本完整保留。
- **表达偏好**：点击方案按钮后，偏好进入讨论输入框；补充意见并点击「保存讨论」才写入项目。
- **讨论**：AI 建议和人的回复按原作者保留。输入框支持 Markdown 及未保存预览；桌面讨论区宽度可以拖动调整。
- **修改候选**：编辑和保存完整规则，尚未确认的候选不替代正式版本。旧版和来源详情按需展开。
- **确认与修订**：审阅后确认单条或整组口径。需要修改有效规则时开启修订；新版确认前旧版继续有效，也可取消修订。
- **复制交接说明**：先保存本轮意见，再手动通知 AI 读取项目，也可以点击「复制交接说明」，将说明粘贴到 AI 对话中继续。网页不会自动启动 AI 对话。

暂未确认的前序决定会阻止依赖它的口径确认；前序版本变化时，相关规则需要复核。AI 负责组织主题和准备完整候选，审阅者决定具体内容。

底部显示连接与未保存状态。网络中断时保留本地输入；恢复后使用「刷新项目记录」核对保存情况。遇到版本冲突，先比较最新记录再提交。关闭浏览器或换设备前，请显式保存需要保留的草稿。

## 远程访问

选择与现有网络环境匹配的方式。`--public-origin` 只设置返回链接的外部地址；端口转发、域名和 HTTPS 由部署环境提供。

### SSH 转发

如果工作台运行在另一台可以 SSH 登录的电脑上，在审阅用的电脑执行：

```sh
ssh -N -L 5322:127.0.0.1:5322 user@project-host
```

将 `user@project-host` 换为实际 SSH 目标，并保持连接。之后可用服务返回的 `http://127.0.0.1:5322/…` 链接访问，输入同一个站点密码。若本机 5322 已占用，可更换 `-L` 左侧端口，同时替换链接中的端口，保留项目路径。

### FRP 或 HTTPS 反向代理

将外部地址转发到项目电脑上的 `127.0.0.1:5322`，并设置相同的外部地址：

```sh
uv run --project council oppencouncil open /absolute/path/to/project --port 5322 --public-origin https://council.example.com
```

把示例域名换为实际域名。工作台页面、脚本和 API 都使用这个站点，应转发整个站点。先在本机完成首次密码设置，再分享项目链接；远程审阅者输入同一个站点密码。公开网络使用 HTTPS 代理保护传输。

## 站点密码

- **首次设置**：未设置密码时，首页或任意项目链接都会显示设置页。输入两次相同的 8–128 字符密码，即可进入；不设用户名。设置只允许成功一次，已设密码不能通过首次设置接口覆盖。
- **再次访问**：使用同一密码登录本站所有已启用项目。登录后返回原项目、问题或主题链接。新链接不携带登录密钥，旧链接中的密钥不再用于认证。
- **退出与过期**：目录和工作台上方均有「退出」。退出会撤销当前浏览器会话；其他已登录设备保持登录。会话最长 12 小时，服务重启后重新登录。工作台存在未保存修改时先保存再退出；会话过期时可在新页登录，再回原页面刷新，草稿保留。
- **保存位置**：密码以随机盐及 PBKDF2-SHA256 校验值保存在站点目录的 `.auth/password.json`，不保存明文、不放入项目记录或 Git。密码随站点目录保留，停止或重启服务不会清除它。浏览器会话使用 HttpOnly、SameSite Cookie；配置 HTTPS 外部地址时启用 Secure。登录与设置均限制尝试频率。

密码用于网页访问；本地 CLI 和已经授权的 MCP 仍按各自权限读取项目文件。

站点密码设置、项目登记和口径写入均使用文件锁协调并发操作；不读取其他进程已锁定的字节。项目文本采用 UTF-8，恢复历史资料时兼容 LF 和 Windows CRLF 换行，并仍以文件原始字节核对来源。服务启动不依赖地址的反向 DNS 查询。

### 免密访问

需要免密访问的可信环境可以显式使用：

```sh
uv run --project council oppencouncil open /absolute/path/to/project --port 5322 --no-auth
```

**免密模式下，能访问该站点的人可查看已启用项目、写入讨论、修改候选并确认口径。** 对外转发时请同时设置实际 `--public-origin`，并自行控制访问范围。需要局域网直接访问时，可显式添加 `--host 0.0.0.0` 并配置防火墙。

`--no-auth` 仅用于尚未设置密码的独立站点，例如合成演示。已设密码的站点会拒绝此选项，避免意外绕过密码。

已启动服务会复用原端口、监听地址和认证方式。要改变这些设置，先 `stop`，再以完整的新参数 `open`；配置不匹配时不会自动修改正在运行的服务。

## 站点目录

源码安装默认在 `council/` 中保存运行文件；wheel 安装默认使用 `~/.local/share/OppenCouncil`。可以把站点状态与源码分开：

```sh
uv run --project council oppencouncil --directory /absolute/path/to/council-site open /absolute/path/to/project --port 5322
uv run --project council oppencouncil --directory /absolute/path/to/council-site status
uv run --project council oppencouncil --directory /absolute/path/to/council-site stop
```

`--directory` 位于子命令之前；后续管理命令应使用同一目录。也可通过 `OPPEN_COUNCIL_DIRECTORY` 设置。

| 文件或目录 | 内容 |
| --- | --- |
| 站点目录下 `projects.local.json` | 项目名称、根路径、编号和启用状态 |
| 站点目录下 `.runtime/` | 服务进程、管理令牌和运行状态 |
| 站点目录下 `.auth/` | 持久化的密码校验值；应保密并随站点备份 |
| 每个项目的 `Freeze/` | 问题、方案、讨论、候选、确认版本及相关记录 |

项目移动后需要重新登记；原根目录不可用时会显示暂不可用，不会自动创建替代项目。备份口径记录应包含完整 `Freeze/` 目录；服务停止后再备份运行状态文件。

## 更容易审阅的方案与参数

方案比较和口径正文支持 Markdown。请让 AI 将每条独立规则写成带标签的段落或列表，即使这些规则属于同一个问题。需要整体理解的执行路线分别比较；共同规则集中说明，每列突出差异，完整条文保留在候选中。能独立选择的维度放在对应条目，避免将各维度的所有组合展开为多套方案。等待时长、次数上限等局部参数可直接在文字中选择：

```text
- **等待时长：**{{choice:retry_seconds;重试等待;5秒;10秒;30秒}}
- **次数上限：**{{choice:retry_limit;最多重试;1次;2次;3次}}
```

该语法可用于方案比较或讨论。网页会将它显示为下拉选项，并在当前浏览器记住选择。“添加到讨论”会把参数名称和取值写入讨论输入框，连续添加时自动用标点分隔；检查后再保存。选择尚不代表口径生效，也不会自动重算其他规则，请让 AI 根据保存的偏好核对联动影响并更新完整候选。

讨论、方案和口径中的完整问题编号（例如 F-000013）会链接到本项目对应问题；代码格式中的编号保留为代码。讨论支持 Windows 的 Ctrl+Enter、macOS 的 Cmd+Enter 保存，也可以点击保存按钮。

## 可选 MCP 与数据接口

MCP 让获准的 AI 客户端参与同一份项目记录。安装与授权见 [MCP 接入指南](../mcp/README.md)。站点登记、MCP 项目列表和 Freeze 读写授权各自独立；开放网页不等于开放 MCP。MCP 直接使用共享存储包，工作台停止时仍能操作其获准项目。

AI 可通过 `import` 批量追加问题，通过 `ai-change` 更新意见或候选，通过 `group-change` 管理主题和共享讨论；这些命令不能替人确认正式版本。skill 提供所需数据格式和内容准备流程。

需要读取完整快照或导出一条正式口径时：

```sh
uv run --project council oppencouncil snapshot /absolute/path/to/project
uv run --project council oppencouncil definition /absolute/path/to/project --question F-000001 --format markdown
```

仅有候选、尚无正式版本时，不能将候选当成已确认的定义导出。读取指定历史版本可加 `--version-number 1`。

## 旧项目与迁移

已有 v3 项目兼容使用，无需为打开工作台强制迁移。旧仓库、运行服务和 skill 安装路径的迁移见 [迁移指南](../docs/migration.md)。

有历史协议、答复或讨论需要整理进工作台时，请让 AI 先核对原始来源和后续修改，使用 `recover` 或 `reconcile` 的 `--check` 预览。不要把讨论摘要自动提升为正式版本。具体批次格式见原治理 skill 的 `references/freeze-workbench.md`。

仍有旧版单项目网页标签页需要保存草稿时，可给 `start` 显式指定 `--legacy-project /absolute/path/to/project`；目标须已登记。该兼容映射默认关闭，新工作台使用带项目编号的接口。

## 常见问题

| 情况 | 处理方法 |
| --- | --- |
| 页面提示使用完整链接 | 运行 `status /absolute/path/to/project`，重新打开返回的完整项目链接。 |
| 提示项目治理标记不匹配 | 确认路径是具体项目根目录，让原治理 skill 检查项目入口；不要手工伪造标记。 |
| 项目暂不可用 | 检查磁盘是否挂载、路径是否移动及当前账户读取权限。 |
| AI 尚未准备候选或前序未完成 | 把缺口交给 AI 补齐后再审阅；表达偏好不等于可以正式确认。 |
| 修改端口或访问方式没有生效 | 在同一站点目录下停止服务，再用所需完整参数启动。 |
| 看不到刚更新的页面 | 刷新浏览器；后端代码更新后还需按原配置重启服务。 |

以下两节记录正式版本与联合确认的具体行为，供需要了解数据接口的使用者查阅。

## 正式口径的唯一来源

从 OppenCouncil 0.1.3 起，每题独立管理口径版本：讨论存建议、选项、示例与交流；候选文档保存完整规则、范围、条件及例外；正式口径保存人类确认的完整原文。AI 通常起草候选，人类可以修改。点击 **确认并生效** 后，确认回执、正文校验值、正式版本及当前指针在一次原子写入中保存，刷新或重开仍读取同一记录。

候选内容的验收由项目 AI 按治理 skill 执行：查清所引用的既有规则，写出足以确定结果的细节，绑定准确来源，以正常、边界及缺失/冲突案例检查是否仍有两种不同执行解释。用户要求核查的事实应先核查；不能将其改写成“本条不负责”后宣称完成。讨论保留已固定规则、核验依据、案例结果及未闭合依赖。交接摘要携带此要求。页面的“有正式口径”只统计确认记录；保存、哈希校验和软件测试不证明语义完整，应用不以字数或关键词冒充内容质量判定。

唯一来源为 `Freeze/questions/F-NNNNNN.json` 的 `definition`。`current_version` 选择 `versions` 中的有效版本；`draft` 保存候选及修改历史。后续版本需人类显式开启；讨论或编辑候选时旧版继续有效，新版确认后旧版保留为只读历史。每题版本独立，轮次不会批量改版本。撤回候选保留撤回记录。MCP/AI 只能修改候选，不能执行确认、开启修订或撤回。

```text
oppencouncil definition PROJECT --question F-000001
oppencouncil definition PROJECT --question F-000001 --version-number 1
oppencouncil definition PROJECT --question F-000001 --format markdown
```

CLI、网页、MCP 与 Python `read_definition` 都读取同一文件。返回的 ID、版本和 SHA-256 可用于记录实现/分析采用的口径。两个 v4 skill 均支持将这个 JSON 以 `--section definition` 登记为 Canonical。其他文档仅引用该记录或生成只读展示，不另写一份需要同步的正式口径。文本确认不等于代码已经实现或分析已经运行。

原生 v3 项目继续兼容；两个 helper 的 `upgrade-v4 --check/--apply` 只升级治理标记，不自动把历史答复、意见或恢复摘要提升为正式版本。旧 Markdown owner 在逐项完成采用及显式所有权迁移前保持原有权威。迁移时保留完整原文、确认依据和来源，避免把摘要冒充正式口径。

## 共同决策与依赖

Status: frozen

共同决策组保存完整组合方案、共享讨论；每条成员口径仍使用原来的编号与独立正式版本。分组新建、调整和依赖配置由 AI 通过 CLI/MCP 管理。网页只提供方案比较、讨论、候选编辑和正式确认。方案倾向仅进入讨论。分组用于共同审阅，每条口径仍可单独冻结：卡片上的“确认并冻结本条口径”只保存该条正式版本，其他成员、候选和讨论保持原状态。同组未完成条目不会仅因分组而阻塞它。底部整组确认是可选的批量操作。人类整组确认前，后端检查所有候选、组版本和依赖版本；任一过期或缺少规则均拒绝整次确认。未改变的成员不产生新版本。人类可取消整组修订：先核对所审阅的组与成员版本，再一次性归档候选及未保存的本地编辑；当前正式版本、版本历史和讨论不变。取消不产生新正式版本，失败时不部分撤回。AI/CLI/MCP 无确认或取消权限。

候选可声明 required、conditional（带条件及是否适用）、reference 三类依赖。前两类适用时需要已确认且准确绑定的前序；组内新版本也可通过显式整组确认共同确定。首次尚未绑定版本的前序确认后，刷新候选会将其当前正式版本纳入本条审阅凭据；点击单条确认才写入该绑定。审阅后前序再变化则拒绝确认，已有的旧版本绑定不会自动更新。循环依赖仍需整组确认，不能逐条绕过。上游打开草稿不改变当前依据；上游正式更新后，下游显示等待/待复核，旧正文仍完整保留。兼容性复核记录带当时版本绑定和理由；规则变化必须走人类开启修订与确认。

组记录位于 `Freeze/decision-groups.json`，只引用成员正式版本。项目读写共用 Freeze 锁；整组确认以 fsync 日志作为提交点，写入中断后由下一次受支持读写先恢复全部记录。业务读者使用 `snapshot`、`definition` 或 MCP，不直接扫描多个 JSON 作为同一时点快照。日志和各记录有大小限制，提交前校验。首次写组/依赖将 manifest 升为 schema 2，旧版本拒绝操作；必须先更新所有读写服务。旧的无组项目仍保持 schema 1。

`presentation` 同时更新讨论正文与选项；可同时提供 `why` 和 `source_summary` 更新背景与来源说明，省略时保留原值，旧值存入后台 `review_notes.previous_context`。这些展示更新不改变用户留言、正式版本或批准状态；`review_note` 单独保存客观核验记录。工作台默认展示人需要理解的方案，哈希和机器核验记录只保留在后台供 AI/MCP 读取，不在网页中展示。相关接口及样例见 skill 的 `references/freeze-groups.md`。

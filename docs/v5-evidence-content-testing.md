# Evidence content and independent Skill trials

The reported defect was substantive: review cards showed verification bookkeeping
and broad limitations in place of findings that help a person decide. The repair
adds a source `summary`, distinct from `read_scope`, and routes review preparation
through the evidence reference. The UI renders that saved substance before its
linked judgments. It does not invent or silently repair source text.

## Method

Fresh agents received the actual Skill, an ordinary review request and bounded
copies of existing review records and aggregate checks. No raw datasets or models
were copied, and all submissions went to isolated temporary projects through the
normal helper. Original papers and official documentation were available. Reads,
helper calls, input hashes and saved artifacts were recorded; the evaluator kept
the rubric and previous corrections outside the cases. Previously coached drafts
are excluded from passing evidence.

These were private-record acceptance cases, not the fictional public fixtures in
`tests/evals/skill_decisions.json`. Their contents and project paths are excluded
from product source. A small number of cases cannot establish reliable behavior
across projects or replace inspection of the resulting live review.
Exact Skill hashes, observed reference reads and submission exit codes are in the
[sanitized run record](../tests/evals/results/evidence-content-20261016.json).

## Paired comparisons

The first pair compared longer semantic guidance against the same new field
interface without that guidance. Both produced useful study methods and findings,
and both correctly distinguished a local numerical consistency check from source
accuracy. Both still presented a confirmation record as substantive evidence and
mixed operational comments into review content. The longer paragraphs showed no
clear advantage and were removed.

The second pair changed only one short paragraph: confirmation establishes the
current rule, not its scientific merits; operational reports belong in comments
or Audit; limitations should accompany the relevant inference. Both arms retained
the same source field interface and rendering. Raw evidence and review inputs
matched; only bootstrap timestamps differed outside the review records.

The retained paragraph's arm separated local observations, literature findings
and recommendation rationale, and omitted the confirmation-only source. The
deletion arm again attached that source to a combined judgment and retained more
operational prose. Both accurately reported the study's population and key
results, and neither claimed the paper proved the local choice superior. Some
repetition of limitations remains even in the retained arm; this is an observed
improvement, not a guarantee of concise writing.

The retained arm also used the normal reassessment path to request review of the
unchanged formal version. The deletion arm stopped in preparation after a rejected
human-review transition and disclosed that limitation. This workflow difference
is recorded, not attributed causally to the paragraph from one trial.

All existing evidence versions, formal definitions and human messages were
unchanged. Updating shared sources caused normal system notifications in other
records; those notifications are not direct edits to their scientific content.

## Transfer case

A fresh agent used the final Skill on a different four-member comparison group.
It saved substantive method summaries, a concrete comparison of the existing
alternatives, and exact evidence bindings through normal work and group commits.
It distinguished literature principles from project-chosen parameters and
reported an inaccessible original paper rather than claiming to have read it.

The evaluator read both options, all four members and all nine linked sources in
the real browser renderer. Current candidate text, dependencies, option rules,
formal versions and human choices were preserved; candidate review-basis pointers
changed with the new evidence, as intended. Old evidence remained immutable.
Shared-source notifications affected five other records without changing their
review text or definitions. The original technical candidate prose remains dense;
this case supports source-content and submission behavior, not wholesale approval
of every existing paragraph.

## Full-scope failure and delegated revision

The next fresh run completed normal submissions for all 51 questions and ten
options. The evaluator read all of those views and 31 distinct cited source
cards in the actual browser. It failed content acceptance: several empirical
papers were reduced to a topic and limitations without population, design or
relevant results; sources supporting different inferences were attached to one
claim describing the entire current rule; a broadly reused authority card still
contained preservation and hash bookkeeping. Useful alternative comparisons and
successful helper validation did not offset those failures.

The candidate Skill now specifies the substance needed for empirical studies,
methods and local checks, and separates claims when their supporting sources
differ. At the user's request, broad reviews explicitly delegate coherent
decision scopes to subagents. Each reads the Skill and prepares complete source
and claim content; the coordinator resolves shared sources, writes through the
helper and reads the resulting pages. A new fresh-context full-scope trial uses
the same ordinary request and original inputs, without instructions outside the
Skill to delegate or fix the observed defects. These requirements and delegation
changed together; improvements cannot be attributed to delegation alone.

The coordinator initially received `agent thread limit reached` and used the
Skill's sequential fallback. After a stale completed test task was closed, it
successfully delegated historical and ungrouped questions to two child agents.
The environment change was reported without content feedback. Both children
prepared drafts and the coordinator integrated them through the normal helper.
The evaluator read all 51 questions, ten options and 31 distinct source cards.
Study summaries now contained substantially more useful methods and results,
and historical explanations recovered missing comparison and event-branch detail.
The result still failed content acceptance: some claims retained unrelated
sources, an alternative without domain learning cited the domain-learning
rationale without distinguishing its role, and a candidate's old verification
status contradicted its updated evidence. Status-preservation prose also remained
in an option's rationale.

The next candidate adds a separate review role after integration. A reviewer
reads saved content and original sources, reports concrete defects, and the
coordinator resolves them through the helper. Its full-scope trial starts again
from the original records with the same ordinary request. Neither the coordinator
nor its reviewers receive the evaluator's findings. The reviewers independently
found missing assumptions, overstatements of what a saved experiment tested,
incorrect attribution of an independent-validation design to a tutorial, and
local evidence summaries that omitted their actual scope. The coordinator saved
repairs through the helper and read the affected pages. One reviewer was reused
on a different scope it had not prepared; that was independent of preparation,
but not a new context for every scope. Agent capacity also required sequential
review. Historical-scope review also found compressed categorical definitions and
a laboratory-specific selection rule incorrectly described as a generic rule;
the coordinator repaired them and the reviewer read back those corrections.

The evaluator has read all 51 questions and ten options in this trial. Despite
the factual improvements, different options still cite the same combined member
claims, including a default policy that does not apply to the selected alternative.
Independent review did not catch that defect. The trial therefore does not
establish complete content acceptance or make a subsequent live review optional.

The trial also exposed incomplete delegation: only one group had a preparation
subagent, while the coordinator prepared the other 47 questions. The final role
wording now assigns preparation of every scope in capacity-limited batches and
starts both preparation and review with fresh contexts and file pointers. This
clarification follows the user's request to avoid one agent carrying the full
workload. It was not present in the preceding full-scope trial; its actual routing
still needs to be observed in the subsequent installed workflow.

## Option-specific reasoning comparison

A focused pair starts from identical saved records after the completed first two
scopes above. Both agents receive the same ordinary request to review a seven-member,
four-option group. The only Skill difference is a short paragraph requiring
option-specific claims where reasoning differs, while allowing shared findings
and explicitly identified comparisons. Original source summaries are already
present in the input and are not credited to this paragraph.

The paragraph arm created distinct claims for all four options, removed the
default-policy claims from alternatives where they did not apply, and explained
the consequences with the same clearly hypothetical examples. The evaluator
read seven members, all four options and eleven source cards in the browser.
Scientific candidate bodies, dependencies, formal versions, human choices and
old evidence were preserved. Option rule summaries were rewritten for clarity;
they are not byte-identical to the input. The agent could not start an independent
reviewer because the available slots were occupied, and recorded that limitation.
The deletion arm also created separate option claims and, during its own final
readback, removed the inappropriate net/RMST claim from the CIF alternative. It
still cited the complete-window index cutoff as a judgment for the short-followup
alternative, without identifying it as a comparison. The evaluator reread the
final alternatives after submission. Both arms lacked an independent reviewer
because the available slots were occupied, and both rewrote option summary cells
while preserving scientific candidate bodies and human confirmations. This single
paired result supports retaining the short paragraph; it does not establish
reliable behavior across projects.

Temporary-case results do not establish live-project completion, installation
or publication.

## Program checks

Bounded checks covered source validation and atomic rejection, append-only
submission/readback, summary rendering and legacy fallback, MCP disclosure, and
historical closed-state display. Council workflow/review tests passed 118, MCP
tests 12, Skill update/integration tests 58, and the frontend suite 115. A loopback
permission failure was rerun with the required permission; it was not treated as
a product failure or silently counted as a pass. The Skill entry validator and
changed-code lint checks passed. Decision Memory and the product version remain
unchanged.

## Installed workflow observation

Commit 1493600 was installed locally at version 5.0.1. Council and MCP restarted
and their health checks passed; installed Skill Markdown matched the development
bundle. An ordinary review request was sent to the existing project chat without
the evaluator's answers. Three preparation subagents started, but the coordinator
prepared sixteen historical items while those slots were occupied. Their browser
readback recovered concrete rules and historical reasons, with repetitive
source/claim text still present. The role wording now explicitly queues remaining
preparation scopes for the next available slot; sequential fallback applies when
the environment cannot run subagents. Live content acceptance is still underway.

## Independent browser-review wording checks

Two subsequent pairs tested additional review wording without supplying expected
defects or correction text. Each covered twelve existing questions and one group
with two inline alternatives. These were read-only reviews, not new preparation
or repair runs.

The first pair received identical rendered exports and original records. Both
arms identified incomplete export coverage and inconsistent historical status
wording. Neither established an advantage for adding a reminder to apply the
completeness checks to existing displayed content. The evaluator then opened the
recovered-source sections and inline control in the real webpage: the full table
and categorical definitions were present. Missing export content was not evidence
that the product lacked those records. The extra wording was not admitted.

The second pair could independently use the actual browser. Its candidate changed
the reviewer sentence from reading saved records to explicitly reading questions,
options and cited source cards in the webpage. Both arms used the browser. The
unchanged-Skill arm inspected expanded history and identified a missing current
cleaning paragraph; the candidate overstated the issue as an absent table. Both
found current-versus-historical explanation problems. This pair did not support
the replacement, which also was not admitted.

The original reports were passed to the existing coordinator as normal review
inputs under the installed Skill, with instructions to check them rather than
treat them as authority. No evaluator-authored scientific answer was supplied.
The coordinator independently rejected the overbroad missing-table finding and
completed the normal correction/readback cycle for the missing current rules and
historical-status explanations. This is a repeated review workflow,
not evidence of a flawless first pass. It does not measure token savings or prove
that delegation prevents compression.

The evaluator also read the question-specific source context for all 51 questions
and all ten option-specific panels. Reading a shared source once is insufficient
to verify every claim attached to it. This final pass found a deterministic link
extraction defect: citation punctuation and a parenthesized access date could be
included in a generated original-source URL. The renderer now terminates URLs at
those delimiters while retaining legitimate paths, queries and fragments. All 13
source-panel unit tests passed, including this regression; no source record or
scientific choice is rewritten by the rendering fix.

## Human review and task boundaries

The user subsequently required project-definition choices to be discussed and
collected in Council, with chat used to link to the pending item. Operational
questions and an explicit request to discuss a choice in chat remain exceptions.
The live workflow produced a plain-language choice with two working options in
Council; the evaluator opened the options without selecting or saving one.

The user also required task parallelism with identical responsibilities for every
scope owner. The current Skill therefore assigns each complete decision scope to
one agent for source checks, complete preparation, self-review and webpage readback.
The coordinator integrates through the normal helper and performs final webpage
acceptance. The former separate reviewer-agent role is removed. Earlier trials
above describe the earlier workflow and are not evidence for this revised one.

Readability changes retain the existing navigation, full text, option comparison,
discussion and source controls. Substantive text uses dark ink, larger type and
clear section spacing; source interpretations are visually grouped with their
conditions. A missing closing tag in the original-link controls was also fixed so
findings are outside the link layout. The relevant 102 frontend checks passed.
The actual installed webpage was inspected at desktop and narrow widths; no
document-wide horizontal overflow was observed. Source-paragraph organization is
also part of the Skill, rather than a renderer-generated rewrite of the evidence.

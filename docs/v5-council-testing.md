# Council 分诊行为评测

2026-10-14。覆盖 OPP-19-01、02 的两种合成场景及一条候选规则的删除比较。本批只验证这两个早期场景；其他范围的后续证据汇总于 v5-acceptance.md。

## 场景、隔离和观察

每个场景分别运行候选规则版、删除该规则版、4.3.1 原始 Stepwise 指令版，共六个独立 Agent。各 Agent 只收到自己的临时目录、请求、Skill 和原始合成资料；rubric 与分组 manifest 留给评测者。使用相同的 v5 CLI 适配说明，所有读取与 CLI 调用通过包装器记录。旧指令来自提交 `a871bea87add686eece05ac6ac28c6e58c7ea869`，并非重新概括的“旧版”。

- 上游删行：原始 10 条合资格记录中 2 条 sex 缺失，生产脚本删除这 2 条，生成表为 8 条、零缺失。既有 F 要求保留全部合资格记录。三组均直接检查原始输入和脚本，识别未经确认的删除；保存 `evidence/needs_check` 和具体待核查事项，没有把最终零缺失当作排除理由。
- 无缺失：原始和生成表均为 10 条、零缺失，脚本只按已确认资格筛选。三组均检查上游后以 `closed/not_applicable` 结束调查，保存适用范围与重新核查条件，没有新增 F。

主 Agent 读取了六个项目的完整已保存讨论、阶段、未决事项、正式版本、代码与输入，并核对原始轨迹。六组均保留正式 F 的内容与版本，没有新增候选、修改分析代码或数据，也没有执行人类确认。常规核查没有创建 Memory。结构检查只是复核的一部分，不能代替以上语义判断。

## 规则删除结论

候选规则原文：

> Before excluding a proposed issue, inspect whether upstream transformations already made an unconfirmed choice; the final dataset alone cannot establish that the trigger is absent.

在这两个单次场景中，删除该句后没有观察到分诊质量退化。因此不把它加入运行时 Skill；场景与评分要求保留在评测中。这不证明所有可能的上游处理都已覆盖，也不代表其他规则已通过准入。

## 暴露的问题与修复

1. v5 的读取仍投影 `status: open`，与已关闭调查矛盾。已从 v5 投影移除旧 `status`，保留独立 `historical` 标记；旧代际接口保持原语义。工作流测试覆盖读回、索引与网页快照。
2. 网页筛选数量仍按旧 status 统计。现与实际列表共用筛选函数；覆盖待人类审阅、待 AI 处理、快速确认、需要选择、补查、已排除、历史讨论和依据复核。无正式版本的 v5 详情也不再生成旧状态标签。
3. `work-read.messages` 是未读输入和未决事项所需的讨论片段，不是完整历史。六次提交的讨论均实际保存；参考接口已明确区分增量读回和 `snapshot` 全历史读取。
4. 后续夹具登记了可执行的人群一致性验证。机械项目验证在两种场景都为 `MANAGED_READY`；实际人群检查在上游删行场景失败、无缺失场景通过，准确暴露真实差异。没有用夹具修复抹去本批的验证失败。

修复后，48 项工作流检查、52 项网页组件检查及两个布局的真实 Chromium 场景通过。浏览器覆盖 1440/1920/2560/390 宽度、保存与刷新、示例图、调查留言和当前版本重新确认；筛选计数随人类编辑返回准备阶段、重新确认结束而减少。最初新增浏览器断言因未展开筛选栏，以及误把待准备的已编辑表格计作可审阅而失败，测试操作与阶段预期已校正。

# Research-stage behavior and rule deletion

Each trial compares a stage-specific candidate sentence, the actual shared Skill without that sentence, and the original 4.3.1 Stepwise instructions from commit `a871bea87add686eece05ac6ac28c6e58c7ea869`. Each arm uses a fresh independent agent, an opaque isolated directory and fictional inputs. The evaluator keeps the rubric and arm manifest. The old arm receives the same v5 CLI adapter; all operations are traced. Whitespace word counts include repeated reads and are not model token counts.

## Import and cleaning

The successful initial producer wrote a cleaned three-record CSV and a quality JSON file into Results. Its check covered source data only. The request was to finish the current cleaning stage without changing the specified transformation or expanding analysis. The candidate sentence was:

> Cleaning normally has no article output. Store reusable cleaned data in Data/derived and checks in Audit; a cleaned dataset or quality report is not a Results table.

All three agents corrected the producer, retained all three records and their order, preserved age zero and the missing age, moved reusable data into Data and checks into Audit, and left no Results output. They registered generated data, expanded executable checks, read back their outputs and finished with MANAGED_READY and no errors or warnings. No F, candidate, Memory or release was created. The evaluator deleted generated data from project-only copies and reran the producers; each recreated identical cleaned data and did not recreate Results files.

Each arm's first project validation correctly rejected the seeded misplaced outputs. Other nonzero calls were CLI routing or nested-argument mistakes, recovered from the displayed usage. They are retained in the results, not counted as passes. For later fixtures the common wrapper instructions include explicit examples of nested-command ordering; the Skill's actual `data register TARGET` interface was already correct. Those fixture instructions do not change these recorded trials.

Deleting the candidate sentence caused no observed degradation in this single scenario. It remains outside the runtime Skill. The behavior and edge case remain in the rubric; this result does not establish performance on arbitrary real cleaning tasks.

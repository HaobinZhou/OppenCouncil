# OppenCouncil 5.0.0

5.0.0 重构了从 AI 查证、准备方案，到你审阅确认、再继续执行的工作流程。AI 先把事实查清，把需要你决定的事集中放到网页里。你可以看推荐依据、修改候选文字和图表规格，再让 AI 从这一轮反馈接着做。

## 重点更新

- **先筛问题，再交给你。** 新的调查流程要求 AI 先判断问题是否存在、已有口径是否覆盖、能否从代码或数据中查清。网页按“需要选择”“快速确认”“补查中／阻塞”“已排除”组织事项。通行做法有依据，就给推荐答案；确实存在取舍，再说明各方案对当前项目的影响。排除理由也会留下，出现新情况时可以重新调查。

- **推荐有出处，也说明为什么适用。** 文献、代码核查、数据事实和测量结果可以独立保存为证据，并关联到具体口径。科研方案会说明通行做法、支持依据、适用条件，以及偏离通行做法的理由。通过 MCP 接入的 AI 助手可以补充资料、反例或意见，由本地 Agent 核对后纳入审阅材料。

- **反馈可以逐条接着处理。** 留言、已保存的候选修改和表格编辑都会进入待处理反馈。Agent 按新增输入继续工作，为每条意见记录回应；暂时解决不了的事项保留问题、原因和继续条件。下一轮可以接着处理新反馈和已经具备条件的事项，不用每次重新整理整场讨论。

- **在网页里直接审表、改表、看图。** 正式图表可以先用模拟样例确认规格。表头、行列、单元格和脚注都能在审阅页编辑，保存后交给 AI 继续。图片样例保留当时的副本，后续重画不会改变历史版本。正式产出关联已确认的规格和生成脚本；规格没变的数据重跑沿用原确认。

- **依据变了，可以重新确认原口径。** 证据更新后，可以标明受影响的口径并重新审阅。如果正文和依赖不变，只是在新依据下再次确认，就把确认记录追加到当前版本。需要修改口径正文时，再提出候选修订并确认新版本。

- **科研和普通项目使用同一个 skill。** 新的 `oppencouncil` 入口统一管理两类项目，科研流程可以使用 R、Python 或其他语言。项目类型决定需要哪些依据、如何组织正式产出；`oppen-project-steward` 和 `stepwise-r-project` 两个旧名称继续可用。

## 安装与升级

完整安装包是 **OppenCouncil-5.0.0.zip**，包含工作台、skills 和可选 MCP；wheel 和 tar.gz 仅包含 Council Python 组件。安装步骤见 [README](https://github.com/HaobinZhou/OppenCouncil#quick-start)／[中文版](https://github.com/HaobinZhou/OppenCouncil/blob/main/README.zh-CN.md#快速开始)。

**可以先升级软件，让已有项目继续留在 v3/v4。** 要使用 v5 项目流程时，再单独生成并审阅迁移计划。迁移保留原有口径及历史、讨论、Memory 和产出登记，未解决的 Attention 转为调查事项继续保留。具体步骤见[升级与迁移指南](https://github.com/HaobinZhou/OppenCouncil/blob/main/docs/migration.md)。

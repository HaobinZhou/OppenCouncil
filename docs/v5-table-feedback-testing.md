# Human table-edit continuation (2026-10-14)

One fresh independent agent received the actual shared Skill, one fictional project, and a request to synchronize a human-edited candidate and simulated example. The evaluator's rubric and prior conclusions were withheld. The human had changed the title, removed BMI, placed Group B before Group A, and added a formatting footnote. Confirmed v1 and its current Results already existed.

The saved candidate retains all four changes, and its newly generated SVG is a content-addressed `Freeze/assets/` copy. The agent replied to and consumed the original feedback, left the item in human review, and made no confirmation, release or Memory entry. The formal definition, Results bytes and old image remain unchanged. An evaluator replay in a copy containing only project files regenerated both the original formal CSV and the new preview byte-for-byte. The preview values remain associated with their column IDs after reordering. A separate Chromium rendering was inspected: all seven lines, including the simulation label and footnotes, are visible without clipping.

The preregistered criterion requiring the original formal producer's bytes to remain unchanged **did not pass**. The agent refactored that producer into a shared CSV writer used by the preview; its default input still selects confirmed v1. This was within the request to synchronize code, and the separate replay establishes unchanged v1 output, but it is reported as a rubric deviation rather than silently redefining a full pass. No additional runtime rule was admitted on this basis.

Actual trace measurements: 2,593 whitespace-delimited instruction words, 20 CLI/script calls and three rejected commits. Two rejections required original-text evidence for the output specification; the final saved basis uses the actual human layout text, with code checks kept separate. The third rejection treated a visual-inspection limitation as a decisive objection; the agent corrected its placement to an applicability limit. These are observed costs, not successful calls.

The run also exposed a continuation-condition defect: an existing formal v1 immediately satisfied an unqualified `definition_confirmed` wait for its edited candidate. The agent used an explicit unsatisfied local assessment as a workaround. The product now saves the existing `min_version` field when a condition is first written: a present candidate means the next formal version; otherwise the current version or first confirmation. The threshold survives withdrawal and later pending-item edits. Binding occurs after all changes in the same transaction, so their order cannot change the result. Explicit version requirements retain their meaning. Evidence-only reconfirmation remains an explicitly assessed condition because it does not increment the version.

Reviewing the original-text rejections against the approved design also identified an overly broad program gate. The design permits directly checked project facts and engineering constraints, even when they support a research output specification. The corrected gate accepts code/data checks or measurements for those source types, while still requiring full-text verification for literature and rejecting abstract-only/model-only facts. Tests cover both positive and negative cases without relabelling literature. The original agent's workaround and failed calls remain unchanged in the recorded evidence.

Workflow/review regression tests passed 86 on macOS and Windows. The Linux follow-up passed 105 tests including those workflows and project checks. The independent agent was not rerun or retrospectively counted as having used the fixed API.
